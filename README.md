# CAES-PINN Benchmark

A reproducible synthetic benchmark for the inverse estimation of the wall
convective heat-transfer coefficient of a compressed-air energy storage
(CAES) cavern, comparing classical least-squares inversion with a
physics-informed neural network (PINN).

The benchmark truth is h_w = 30.0000 W m^-2 K^-1. Classical inversion on
noisy data recovers 30.0774 +/- 0.6970 W m^-2 K^-1 (0.11 sigma from truth,
reduced chi-squared 1.051). The PINN learns 28.6684 W m^-2 K^-1 (1.90 sigma
low) while reconstructing the temperature field to 0.0489 K rms; applying the
classical inversion to that reconstructed field returns the truth to within
0.08 sigma.

This repository accompanies the paper (under review). Full problem
definition, equations and results are given there.

## Contents

- `code/make_data.py` — reference forward solver and generation of the
  synthetic sensor data.
- `code/sweep_worker.py`, `code/sweep2_worker.py`, `code/sweep3_worker.py` —
  PINN training and the architecture sweep (loss weights, initial values,
  training budgets).
- `code/sens_worker.py`, `sens_mech.py`, `sens_tau.py`, `sens_check.py`,
  `sens_bias.py` — sensitivity, identifiability and Monte-Carlo analyses.
- `data/sensor_data.npz` — noisy sensor records (two sensors, 900 s sampling,
  385 samples each, nominal noise sd 0.2 K).
- `data/bias_analysis.npz` — output of the 3000-realisation Monte-Carlo study.
- `data/paper_numbers_final.json` — machine-readable record of every number
  quoted in the text and tables of the paper. This is the single source of
  truth for all reported values.
- `data/sweep_results/` — per-run JSON output of the fifteen sweep runs
  (twelve valid), from which Table 3 of the paper was built.

`data/reference_solution.npz` is not included; it is regenerated by
`make_data.py`.

## Requirements

Python 3, NumPy, PyTorch (for the sweep workers), Matplotlib.

## Reproducing

Run `code/make_data.py` first to regenerate the reference solution and the
sensor data. The sweep workers can then be run to reproduce the PINN results;
note that a single training run takes 218–686 s on a CPU and the full sweep
about 95 min.

## What is not included

Three items are absent, and are listed here for transparency:

1. **The driver script for the classical inversion.** The estimates in
   Sections 3.1 and 4.1 of the paper, including the central result
   30.0774 +/- 0.6970 W m^-2 K^-1, were produced by a script that was not
   preserved. The procedure is fully specified in the paper (a 33-point
   chi-squared scan from 26.0 to 34.0 W m^-2 K^-1 in steps of 0.25, weighted
   by sigma_r = 0.2 K, with a three-point parabolic fit at the minimum) and
   the input data are in `data/sensor_data.npz`, so it can be reimplemented.
2. **The network checkpoint of the single run reported in Section 3.2.** Its
   training budget and boundary-loss weight were likewise not recorded. That
   run is provenance-limited. The twelve-run sweep in Section 4.4 is not
   affected: its scripts and outputs are both present here.
3. **The figures of the paper.** Figures 2 to 4 were produced in interactive
   notebook cells rather than by a stored script, and no figures are included
   in this repository.
